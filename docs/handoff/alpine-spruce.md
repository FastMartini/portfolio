# Alpine spruce trees

The `c_tree_design_handoff` supplied on October 25, 2026 selects option 1c, Alpine spruce, for the illustrated Climb. [The supplied browser prototype](reference/alpine-spruce-reference.html) is retained as design evidence. Its alternate styles and review query parameters belong to that prototype; the portfolio renders the selected spruce design directly.

`components/climb/mountain/scenery.ts` implements the supplied shapes, colors, glades, crown clearance, and shorter, snowy trees near the treeline. Eighteen fixed SVG definitions (12 spruce and six snowy spruce) are reused through `<use>` instances. `scene.ts` inserts those definitions into the server-built mountain SVG; the client paint layers share them within the same document. Drawing remains deterministic server content; scrolling and resizing do not rebuild the forest.

Tree appearance and thinning use a generator seeded from each tree's position. Each candidate tree still consumes its original single tone draw from the shared scenery generator, even when a glade or clearing removes it. This preserves cloud placement and all terrain output. `tests/fixtures/scenery-before-trees.json` was captured from the original renderer at `41e8848` before replacement; `tests/climb-trees.spec.ts` compares those non-tree layers byte for byte and checks deterministic output and resolved SVG references across Chromium, Firefox, and WebKit.

`tests/climb-mountain.spec.ts` compares the selected prototype and production scenery at desktop and mobile sizes, including tree definitions and `<use>` placements. The unused alternative tree definitions are excluded from the prototype comparison. Existing Landmark artwork checks continue to use the original Climb reference.

The detailed forest made camera travel expensive: inherited weather properties restyled the whole SVG, and animation repainted thousands of tree instances. Weather now updates only the sky, haze, and sun. `mountain/layers.ts` separates static scenery and animated Landmarks into permanent SVG paint layers in their original depth order. HTML wrappers let the browser reuse static paint surfaces independently of the animated artwork. Each layer's viewport uses its measured world bounds, including room for strokes and filters. The camera transform belongs to an HTML wrapper so moving it does not change the SVG itself.

The same vector nodes remain visible during movement and at rest. Flags, smoke, chairlifts, and other decoration keep animating through scroll; reduced motion, List View, and hidden tabs still pause every SVG timeline. The walked trail and climber also remain native SVG. `tests/climb-rendering.spec.ts` checks animation progress and actual chair movement during continuous scrolling, absence of replacement bitmaps, node continuity at rest, world/screen alignment at desktop and mobile sizes, and weather isolation. Reference comparisons and visual snapshots guard artwork and depth order across the layer boundaries.

Measure production scrolling with `SCROLL_URL=http://127.0.0.1:4173/portfolio/ node scripts/measure-climb-scroll.mjs`; set `SCROLL_BROWSER=webkit` for WebKit. `SCROLL_MEAN_BUDGET_MS` optionally makes the command fail above a local frame-time budget. This four-second real-frame probe is deliberately separate from CI's deterministic navigation tests: its absolute timing depends on the machine and graphics stack.
